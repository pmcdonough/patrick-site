The engine is 12 small modules. Each one installs its functions into one shared object and then links to the others, so they can call each other freely while each file stays about one subject.

One tick of the game

Every 0.03 seconds of game time, the engine runs the same sequence. A full game is more than 120,000 ticks and plays in about two seconds when nothing is drawn.

Clock and penalties→ Line changes→ Each skater picks a target→ The carrier reads: shoot, pass, carry→ Skating physics→ Puck physics, saves, blocks→ Offside, icing, whistles

Skaters move with real acceleration and top speeds from NHL EDGE. Their decisions are rules written from coaching references, and the carrier's choice between shooting and passing is priced by the same expected-goal model the stats use.

Same seed, same game, everywhere

Comparing two game plans fairly means playing them through the same luck. That only works if a game is exactly repeatable, which took two pieces of engineering.

A seeded generator

Every random draw in a game comes from one generator seeded by the game's number. Nothing in the engine may call the browser's own random function, and a unit test fails if anything does.

Exact math

Browsers and Node compute sine, cosine, logarithms and powers differently in the last binary digit. That was enough to change how 2 of 20 games ended. The engine now uses its own ports of the standard fdlibm routines, built from exact arithmetic.

Proven, not assumed

Seeded games are played in Node and in Chromium, Firefox and WebKit, and every final number must match to the last digit. Games also replay in reverse order and in the page's own workers to prove no state leaks between them.

How it is kept honest

A seeded run reproduces exactly, so any change in the results is the code's doing. Every change goes through these before it ships.

Shipping

Versions

The site has a version, and each project has its own. A small script sets a project's version and every version stamp that carries it; a test fails if any file disagrees.

Never half a deploy

Every file and import is loaded with its version in the URL, and the host makes browsers check each file on every visit, so a visitor never runs new code against an old module.

One commit per version

Each version is one commit with a changelog entry. The live site updates about a minute after a push.

Built with AI

Nearly all of the code was written by Claude: first in claude.ai chat, one full-repo version at a time, then in Claude Code from the terminal, where it runs the checks itself and commits each version. My part is the product: what to build, how a coach would use it, what a number should mean, and whether the result is right. The checks above are how both of us know a change did what it said.

The engine is about 1,500 lines. The tests, tools and documentation around it are about as large again, and they are the reason it can keep changing safely.
